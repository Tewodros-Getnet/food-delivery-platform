# Fix Splash Screen Transition and App Icons

Applied configuration changes to eliminate splash screen transition by using solid black native splash screens across all three Flutter apps (customer, restaurant, rider). The fix targets the user's complaint about noticeable transitions between native Android splash and Flutter splash screens showing different logo shapes.

**Watch for:** **confirmed** — Critical implementation gap in launch_background.xml files still referencing bitmap drawables instead of solid colors, which will continue to show the original transition problem.

**Verdict**: CHANGES_REQUESTED

## High-level view

The pubspec.yaml configurations are correctly updated across all three apps with solid black splash screens and no image references, which should eliminate the shape mismatch transition. The styles.xml and colors.xml files properly reference the solid #0D0D0D splash background color. However, the launch_background.xml files in all three apps still contain bitmap references to drawable/background files, creating a critical gap that will cause the splash screens to continue displaying background images instead of solid colors. The app icon configurations look properly set up with adaptive icons using the same logo.png file consistently.

<details><summary>Details</summary>

## Pubspec.yaml configurations implemented correctly

All three apps have correct flutter_native_splash configurations with image properties removed and only solid black color (#0D0D0D) remaining. The flutter_launcher_icons sections use consistent adaptive_icon_background and adaptive_icon_foreground settings across all apps.

## Critical gap in launch_background.xml files

The most significant issue discovered is that all three launch_background.xml files still contain layer-list configurations referencing bitmap drawables:

```xml
<layer-list xmlns:android="http://schemas.android.com/apk/res/android">
    <item>
        <bitmap android:gravity="fill" android:src="@drawable/background"/>
    </item>
</layer-list>
```

This configuration will cause the native splash screen to display whatever image is in @drawable/background, completely bypassing the intended solid color splash. The user will continue to see the original transition problem because the native splash is still showing a logo/background image instead of the solid black intended.

For a proper solid color splash, these files should either contain a solid color fill or be regenerated by the flutter_native_splash generator to match the pubspec.yaml configuration.

## Styles and colors properly configured

The styles.xml files correctly reference @color/splash_background for the LaunchTheme windowBackground. The colors.xml files define splash_background as #0D0D0D, matching the pubspec.yaml specification. AndroidManifest.xml files properly reference @style/LaunchTheme.

## App icon setup appears complete

The adaptive icon configuration uses consistent logo.png assets across all apps with #0D0D0D background color. The logo.png files exist in all three apps' assets/images directories.

## Evidence of incomplete generator execution

The presence of old splash PNG files in build directories and the unregenerated launch_background.xml files suggest that either the flutter_native_splash:create generator wasn't run after the pubspec.yaml changes, or the generated files weren't properly committed. The background.png files still exist in drawable directories, which would normally be removed or replaced during proper splash asset regeneration.
